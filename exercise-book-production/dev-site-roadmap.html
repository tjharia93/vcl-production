Where the code lives

Today Fragile

  • A Frappe Web Page (exercise-book-production-v2-dev), edited live over REST.
  • Not in git. Several sessions edit it, and stale copies have overwritten newer ones.
  • The page calls ERPNext's generic REST API directly.

Phase 1 In git

  • The page source sits in vcl-production. A deploy script pulls the live page first and refuses to overwrite a newer one.
  • Stock moves go through whitelisted methods in production_floor (like stores.py), with tests, not raw REST writes.
  • Items, fields and settings are created in after_migrate.

Phase 2 In the app

  • The floor screens become a page of the vcl-production app, next to Production Floor (/app/vcl-production-lite), on floor tablets.
  • Dashboards and order screens live in Compass, beside the orders.
  • The dev page is retired.

Rules the site keeps at every stage

  • Made to stock. Runs are planned by group (brand, size, pages, ruling), never one per Sales Order.
  • One place to enter each station. No second copy on another page.
  • Every floor entry records stock. If it matters, it's in ERPNext, not in a browser.
  • Covers are counted in printed sheets. A4 = 2 books per sheet, A5 = 3. One sheet makes one insert set.
  • The run number travels on every entry, so yield and waste can be read per run.
  • Checks run on the server (school or brand, unit and price), so every screen and import is covered.
  • Floor screens are large and touch-first, with picks instead of typing and a keypad for quantities.
